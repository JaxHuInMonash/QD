## 1. 背景与目标

### 1.1 背景
项目组的任务（Story / Task / Bug）在 Jira 中管理，当前看板为 [Jira 看板 22909](https://jira.dreame.tech/secure/Dashboard.jspa?selectPageId=22909)（示例 Story：[VERA2506M-251](https://jira.dreame.tech/browse/VERA2506M-251)）。成员经常出现"任务状态未及时在 Jira 中更新"的情况，需要一个每日提醒机制。

### 1.2 核心目标
**在项目组内部提醒成员：他们名下有哪些未处理的任务。**

> 本目标在需求澄清中由"同步管理 + 负责人跟进 + 统计"收窄而来，所有设计以"提醒未处理事项"为准，不追求统计、追溯与历史分析。

### 1.3 目标用户

| 角色 | 诉求 | 主要使用方式 |
|---|---|---|
| 研发人员 | 知道自己名下有哪些未完成任务，及时去 Jira 更新 | 接收 17:00 私聊提醒；打开"我的未完成"视图 |
| 测试人员 | 同上；并能查看自己提交的问题进展 | 接收提醒；使用"按报告人查看"视图 |
| 项目负责人 | 了解成员和项目的未完成任务分布 | 使用"按人员查看""按项目查看""状态看板"视图 |
| 运维负责人 | 保证同步和提醒正常运行 | 接收失败通知；维护管理表格中的配置 |

## 2. 范围

### 2.1 本期范围（做）
1. 按 Jira 看板 22909 的范围，同步**未完成**的 Story、Task、Bug 到飞书多维表格（只读）。
2. 每个法定工作日定时同步 2 次，并支持在表格内手动触发同步。
3. 每个法定工作日 17:00，通过飞书机器人**私聊**提醒每位名下有未完成任务的成员。
4. 一张独立的管理表格，维护提醒相关配置。
5. 同步 / 提醒失败时自动重试，并同时通知运维负责人与备份负责人（v1.2）。
6. 🆕 v1.2：年底检查次年节假日日历是否已录入，未录入则提醒运维负责人与备份负责人。

### 2.2 明确不做
| 不做的事项 | 说明 |
|---|---|
| 在表格中修改并回写 Jira | 数据单向流动，Jira 为唯一数据源 |
| 表格中的人工补充字段 | 表格完全只读 |
| 群消息 / 负责人汇总消息 | 提醒只私聊个人 |
| 历史任务保留 | 已完成、移出看板、Jira 已删除的任务从表格中删除 |
| 每日统计快照、趋势统计、燃尽图 | 已取消 |
| 同步日志、通知日志 | 已取消；仅保留当次失败通知。**注**：取消的是业务日志；程序运行日志在运行环境本地保留 7 天，仅用于故障排查，不写入表格、不对用户展示、不记录敏感信息（v1.1） |
| 超期判断、Story-子任务层级展示 | 字段只保留核心字段，不含截止日期、父任务 |
| 改造或处理「敏捷项目管理」表格 | 保持不动，不纳入本项目 |
| 借鉴参考表格「软硬件功能配置 R5088A/R6001A/R500VH」 | 不作为设计约束 |

## 3. 术语与业务规则

| 术语 | 定义 |
|---|---|
| 同步范围 | 以 Jira 看板 22909 所展示的范围为准；看板调整，同步范围随之变化 |
| Issue 类型 | Story、Task、Bug。v1.3 明确对应的 Jira 类型：Story = `Story`；Task = `任务`；Bug = `Bug（软件测试）`、`BUG（实验室）`、`BUG（硬件测试）`；`Fix`、`子任务`（暂不纳入，待最终确认）及其他类型不在范围内 |
| 个人名下 | 该成员为 Issue 的**经办人（Assignee）**；报告人、关注人不计入 |
| 状态展示 | 原样展示 Jira 状态名，不做归并、不维护状态映射表 |
| 未完成 | Jira **状态类别**不是"完成"的 Issue（即状态类别为"待办"或"进行中"） |
| 法定工作日 | 按中国法定节假日安排：法定节假日不算工作日，调休补班日算工作日 |
| 提醒对象 | 同步范围内、名下有未完成任务的经办人，扣除排除名单中的人员。v1.3：没有经办人的任务进入主表格并显示为"未分配"，不发送提醒、不计入未送达 |

**规则 R1：数据单向只读。** Jira 为唯一数据源，表格中的任何同步字段均只读；所有状态修改都在 Jira 中完成。

**规则 R2：表格只保留未完成任务。** 每次同步后，主表格中仅包含同步范围内的未完成任务。任务一旦完成、移出看板范围或在 Jira 中被删除，即从主表格中删除。

**规则 R3：账号对应。** 默认通过**公司邮箱**将 Jira 账号与飞书账号对应；邮箱无法对应的人员，通过管理表格中的"例外对应表"手工补充。

## 4. 功能需求

### F1 Jira 数据同步

| 编号 | 需求 |
|---|---|
| F1.1 | 按 Jira 看板 22909 的范围，获取其中的 Story、Task、Bug |
| F1.2 | 仅将**未完成**的任务写入主表格（见 R2） |
| F1.3 | 已在表格中的任务，同步时更新为 Jira 最新内容；不再满足条件的任务从表格删除 |
| F1.4 | 以 Issue 编号作为每条任务的唯一标识，避免重复 |
| F1.5 | 每次同步后更新"最后同步时间" |

**验收标准**
- 同步完成后，主表格中的任务集合 = 同步范围内未完成任务的集合，无重复、无遗漏。
- 在 Jira 中把某任务改为"完成"类状态后，下一次同步后该任务从表格消失。

### F2 定时同步与手动触发

| 编号 | 需求 |
|---|---|
| F2.1 | 每个**法定工作日**的 **09:00** 与 **16:50** 各自动同步一次；周末与法定节假日不定时同步 |
| F2.2 | 主表格中提供"立即同步"按钮，**仅表格管理员或负责人**可操作（v1.2 明确：主表格所有者朱卓、主表格管理员胡桓康）；v1.3 明确：按钮为主表格**仪表盘中的按钮组件** |
| F2.3 | 手动同步**只更新表格，不发送提醒** |
| F2.4 | 手动同步完成后，在表格中显示结果（完成时间、同步条数、是否成功）；v1.3 修订：不单独记录手动同步结果，由主表格**仪表盘统计组件**展示"最后同步时间"（更新即成功）与"未完成任务数"（同步条数），对所有查看者可见；**失败**时通过异常通知告知运维负责人与备份负责人 |
| F2.5 | 🆕 v1.1：运行环境错过当天（法定工作日）09:00 或 16:50 定时同步时，恢复在线后立即补同步一次；非工作日不补 |

**验收标准**
- 非管理员、非负责人无法触发"立即同步"。
- 周末和法定节假日不产生定时同步；需要时可手动同步。

### F3 每日个人提醒

| 编号 | 需求 |
|---|---|
| F3.1 | 每个**法定工作日 17:00**，向每位提醒对象**私聊**发送一条提醒消息 |
| F3.2 | 提醒依据 16:50 那次同步的结果生成 |
| F3.3 | 名下没有未完成任务的人，当天不发送 |
| F3.4 | 提醒对象自动识别（见第 3 节"提醒对象"），排除名单中的人员不发送 |
| F3.5 | 消息内容格式见第 6 节 |
| F3.6 | 🆕 v1.1：运行环境错过当天 17:00 提醒时，若恢复在线时早于当天 **20:00**（可配置），先补同步再补发提醒；已过 20:00 或已跨天则不再补发；补发与正常提醒规则一致，每人每天最多 1 条 |

**验收标准**
- 法定节假日不发送；调休补班日照常发送。
- 每人每个工作日最多收到 1 条定时提醒。
- 消息中每类任务最多列 3 条，总数与"我的未完成"视图中的数量一致。

### F4 管理表格（配置）

| 编号 | 需求 |
|---|---|
| F4.1 | 独立于主表格，仅运维负责人与备份负责人（管理员）可访问 |
| F4.2 | 维护**排除名单**：列出不接收提醒的人员 |
| F4.3 | 维护**例外对应表**：Jira 账号 ↔ 飞书账号（用于邮箱无法对应的人员） |
| F4.4 | 维护**节假日日历**：标注法定节假日与调休补班日，供定时同步和提醒判断工作日；v1.2：某年份未录入日历时，该年按"周一至周五为工作日"判断 |
| F4.5 | 🆕 v1.2：每年 **12 月 1 日起，每周一 09:00** 检查次年节假日日历是否已录入；未录入则同时私聊提醒运维负责人与备份负责人，录入后停止提醒 |

**验收标准**
- 主表格所在知识库的普通成员无法看到管理表格及其中的邮箱信息。
- 修改排除名单 / 例外对应表后，下一次提醒即按新配置执行。

### F5 异常处理

| 编号 | 需求 |
|---|---|
| F5.1 | 同步失败时自动重试 **1 次**；仍失败则**同时私聊通知运维负责人与备份负责人**，由运维负责人处理，备份负责人必要时接替（v1.2） |
| F5.2 | 当天有人未成功收到提醒（例如账号无法对应、已离职、发送失败），将未送达人员名单汇总后**同时私聊发送给运维负责人与备份负责人**（v1.2） |
| F5.3 | 若 16:50 同步失败，17:00 仍使用**上一次成功同步**的数据照常提醒，并在消息中注明"数据截至 XX 时间" |
| F5.4 | 不记录同步日志与通知日志；失败信息仅通过 F5.1、F5.2 的通知传达。程序运行日志另行本地保留 7 天，仅供排查（v1.1） |
| F5.5 | 🆕 v1.2：提醒消息发送出错时自动重试 **1 次**，仍失败才计入未送达；账号无法对应、已离职的情况不重试，直接计入未送达 |

> 已知代价：不保留日志，事后无法追溯历史上某次提醒未送达的原因，只能依赖当天的失败通知。

## 6. 提醒消息规格

### 6.1 结构
1. 提醒语（例如"请在下班前更新以下任务在 Jira 中的状态"）
2. **Story（共 N 条）**：最多列 3 条
3. **Task（共 N 条）**：最多列 3 条
4. **Bug（共 N 条）**：最多列 3 条
5. 查看全部的链接 → 主表格"我的未完成"视图
6. 数据截至时间

### 6.2 规则
- 只统计和列出**未完成**任务。
- 每类内部按**创建时间从早到晚**排列（创建越早越靠前）；此处的"优先"指排列顺序，与 Jira 优先级字段无关。
- 每条任务显示：**编号（可点击跳转 Jira）+ 标题 + Jira 状态**。
- 某一类数量为 0 时，仍显示该类，写作"共 0 条"（v1.2 确定）。

### 6.3 示例（示意）

```
请在下班前更新以下任务在 Jira 中的状态：

Story（共 5 条）
· VERA2506M-251 某功能需求标题 —— 开发中
· VERA2506M-260 某功能需求标题 —— 待处理
· VERA2506M-273 某功能需求标题 —— 开发中

Task（共 2 条）
· VERA2506M-301 某任务标题 —— 进行中
· VERA2506M-315 某任务标题 —— 待处理

Bug（共 0 条）

查看全部 → 我的未完成
数据截至 11-25 16:50
```

> 示例中的编号、标题、状态均为示意，非真实数据。

**已知风险**
- **状态类别与团队理解不一致**：D2 核对发现（VERA2506M）：Bug 类"已解决 / 无法解决"归为完成（不再提醒）；"duplicate"归为进行中、"Not an issue / 等待release发布"归为待办（仍会提醒）；Story / 任务的"挂起"归为待办（仍会提醒）。系统按 Jira 归类处理，如需调整由 Jira 管理员修改状态类别（v1.3）。
- **看板变动影响范围**：看板筛选条件调整会直接改变同步范围和提醒对象。
- **无日志可追溯**：见 F5 说明（业务层面不可追溯；运行日志本地保留 7 天，可辅助排查近期故障）。
- **一期运行在个人办公电脑**（v1.1）：电脑关机、休眠、断开 VPN 时定时点会错过；按 F2.5、F3.6 补执行，但 20:00 后才恢复在线则当天无提醒。后续视情况迁移到公司内网服务器或容器平台。
