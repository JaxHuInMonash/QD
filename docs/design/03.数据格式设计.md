## 2. 主表格

- 🔒 位置：「敏捷项目管理」所在知识库；所有者朱卓；胡桓康为管理员（D7）；QD助手 应用具备编辑权限。
- 🔒 用户对"未完成任务"数据表**只读**（R1），所有字段由后端写入。

**唯一标识**：Issue 编号（Jira key，如 `VERA2506M-251`）。后端每次同步读取全表，按 Issue 编号与 Jira 结果比对后新增 / 更新 / 删除（F1.3、F1.4）。飞书记录 ID（record_id）仅后端内部使用，不展示。

| 2 | 标题 | 多行文本 | Jira summary 原文 | 人形机器人 APP 首页改版 | |
| 3 | 类型 | 单选 | `Story` / `Task` / `Bug` | Story | 选项固定，由 Jira 类型名映射（见 4.2、Q4） |
| 4 | 所属项目 | 单选 | Jira 项目 key | VERA2506M | 新项目出现时自动新增选项 |
| 5 | 经办人 | 人员（单人） | 飞书 open_id；对应不上留空 | 胡桓康 | "我的未完成"筛选、提醒对象识别（2.2） |

### 2.2 经办人 / 报告人的字段实现（✅ 已确认，Q1）

需要同时满足三条已确认的要求，单一字段无法全部满足：

| 要求 | 来源 | 需要的字段类型 |
|---|---|---|
| "我的未完成"按**当前查看者**自动筛选 | 需求 5.3 | **人员字段**（多维表格只能对人员字段按"当前用户"筛选，⚠️ 需验证） |
| 对应不上的人员显示 **Jira 姓名 +"未对应"** | 01 Q1 / 需求 5.2 注 | **文本字段**（人员字段只能放飞书用户） |
| 字段数 12 个 | 需求 5.2 | — |

已确认方案（Q1 方案 A）：

| 字段 | 类型 | 写入规则 | 用途 |
|---|---|---|---|
| 经办人 | 人员（单人） | 能对应时写入飞书用户；对应不上留空 | "我的未完成"筛选、提醒对象识别 |
| 经办人（显示）🆕 | 单行文本 | 能对应时写飞书姓名；对应不上写 `孙伟（未对应）` | "按人员查看"分组；让未对应人员可见 |
| 报告人 | 单行文本 | 能对应时写飞书姓名；对应不上写 `Jira 姓名（未对应）` | "按报告人查看"分组（无需按当前用户筛选，故一个文本字段即可） |

### 2.4 仪表盘：立即同步按钮与同步结果（✅ 已确认，Q2 方案 D）

不新增任何数据表，在主表格的**仪表盘**中放置以下组件：

| # | 组件 | 类型 | 配置 | 作用 |
|---|---|---|---|---|
| 1 | 立即同步 | 按钮组件 | 点击后触发自动化 / 工作流，把"同步请求"传给后端（方式见 V3）；可选范围限定为朱卓、胡桓康（⚠️ V2） | F2.2 |
| 2 | 最后同步时间 | 统计组件 | 数据源：未完成任务表；统计"最后同步时间"的最大值 | F2.4：完成时间 / 是否成功（时间更新即成功） |
| 3 | 未完成任务数 | 统计组件 | 数据源：未完成任务表；统计记录数 | F2.4：同步条数 |
| 4 | 视图使用说明 | 文本组件 | 各类用户应查看的视图 | 需求 5.3 备注 |

规则：
- 手动同步**不写入任何同步结果记录**；成功与否以统计组件中的"最后同步时间"是否更新为准；**失败**时通过异常通知（同时私聊运维负责人与备份负责人）告知（Q7 修订，见第 11 章）。
- 后端收到同步请求后**校验点击人**是否为朱卓或胡桓康（Q2 权限，02 Q2），不符合则忽略并在运行日志中记录。
- 同步进行中再次收到请求时，不重复执行（后端内存中的"同步中"标记，无需写表）。
- 边界情况：未完成任务表为空时，"最后同步时间"统计无值；仪表盘显示为空，属正常。

## 3. 管理表格

- 🔒 仅胡桓康、朱卓可访问（F4.1）；QD助手 应用具备读取权限。
- 修改后**下一次执行**即生效（F4 验收标准）；后端每次执行时实时读取，不缓存。

### 3.1 数据表「排除名单」

| # | 字段名 | 飞书字段类型 | 必填 | 说明 |
|---|---|---|---|---|
| 1 | Jira 账号 | 单行文本（索引字段） | 是 | Jira 登录名（如 `zhaolei`），匹配依据 |
| 2 | 姓名 | 单行文本 | 否 | 便于人工识别，不参与匹配 |
| 3 | 原因 | 单行文本 | 否 | |

规则：同一 Jira 账号出现多行视为一条；Jira 账号为空的行忽略。

### 3.2 数据表「例外对应表」

| # | 字段名 | 飞书字段类型 | 必填 | 说明 |
|---|---|---|---|---|
| 1 | Jira 账号 | 单行文本（索引字段） | 是 | |
| 2 | 飞书人员 | 人员（单人） | 是 | 对应的飞书用户 |
| 3 | 备注 | 单行文本 | 否 | 如"Jira 使用合作方邮箱" |

规则：仅在**邮箱无法对应**时查本表（R3）；同一 Jira 账号多行时取第一行，并在运行日志记录警告。

### 3.3 数据表「节假日日历」

| # | 字段名 | 飞书字段类型 | 必填 | 说明 |
|---|---|---|---|---|
| 1 | 日期 | 日期（仅日期，索引字段） | 是 | |
| 2 | 类型 | 单选：`法定节假日` / `调休补班` | 是 | |
| 3 | 名称 | 单行文本 | 否 | 如"元旦""国庆节调休" |

规则：
- 某年份"已录入" = 该年份至少有 1 行记录（F4.4、F4.5）；
- 同一日期多行且类型冲突时，以"法定节假日"为准，并在运行日志记录警告；
- 工作日判断：法定节假日 → 非工作日；调休补班 → 工作日；其余按周一至周五（含未录入年份）。

## 4. 外部数据映射

### 4.1 Jira 查询

| 项目 | 内容 |
|---|---|
| 接口 | `GET /rest/api/2/search` |
| 查询条件（JQL） | `{看板 22909 对应筛选器的 JQL}`（依赖 D1）`AND statusCategory != Done AND issuetype in ({Story/Task/Bug 的类型名})` 💡 |

### 4.2 Jira 字段 → 主表格字段

| 主表格字段 | Jira 字段路径 | 转换规则 |

### 4.4 项目 VERA2506M 的类型与状态（2026-11-26 实测，用于 Q4 与依赖项 D2）

数据来源：`GET /rest/api/2/project/VERA2506M/statuses`（胡桓康账号查询）。看板 22909 若包含其他项目，需按 D1 结果对其他项目补充查询。

**与需求相关的类型**

| Jira 类型 | 待办（new） | 进行中（indeterminate） | 完成（done，不进入主表格） |
|---|---|---|---|
| `Story` | backlog / 挂起 / Init初始化 | Story开发中 / Story联调中 / 预测试验收中 / TPM验收中 / 等待版本发布中 / 测试验收Story中 / 临时删除Story分支 / TPM审核完成，待开发中 / 体验check中 / 测试确认中 | 完成 / Story分支已删除 |
| `任务` | 待办 / 挂起 | 开发中 / 代码审核中 / 用例完善中 / 用例审核中 | 完成 |
| `Bug（软件测试）`、`BUG（实验室）`、`BUG（硬件测试）`（三者流程相同） | 重新打开 / 开放 / Not an issue / 等待release发布 | 处理中 / 持续优化 / duplicate / 联调测试 / Track / 等待发布 | 已解决 / close / 无法解决 |
| `Fix` | 待提交 | 测试问题审核人审核中 / 开发问题审核人审核中 / 开发中 / 代码审核中 / 回归测试中 / 待开发 / 问题裁决中 / 联调测试 / 特殊裁决中 / 测试确认中 / 待产品确认 / 产品已确认，需求待释放 / reopen审核中 / BUG单升降级审核 | 完成 / 问题挂起中 / 超期单搁置 |
| `子任务`（subtask） | 待办 / 挂起 | 开发中 / 代码审核中 / 用例完善中 / 用例审核中 | 完成 |

**其他类型**（需求未涉及）：`Epic`、`产品需求`、`改进`、`DQE问题单`、`测试用例`（以上与 Bug 流程相同）；`提测`、`发布检测`、`HotFix版本发布`（版本发布流程）。

**状态类别核对结果（D2）**——以下状态的 Jira 归类可能与团队理解不一致。按已确认规则（需求 R2，"按 Jira 状态类别判断"，不维护映射表），系统将**照 Jira 归类处理**；如需调整，应由 Jira 管理员修改状态类别。

| 类型 | 状态 | Jira 归类 | 对本系统的影响 |
|---|---|---|---|
| Bug 类 | 已解决、无法解决 | 完成 | 不再提醒（需求第 8 章已知风险） |
| Bug 类 | duplicate | 进行中 | 已标记重复的问题**仍会提醒** |
| Bug 类 | Not an issue、等待release发布 | 待办 | **仍会提醒** |
| Story、任务、子任务 | 挂起 | 待办 | 挂起的任务**仍会提醒** |
| Fix | 问题挂起中、超期单搁置 | 完成 | **不再提醒** |

## 5. 本地状态文件

- 路径：`deploy/local/data/reminder-state.json`（迁移到服务器后放在挂载的数据目录）
- 写入时机：每次定时任务执行完成、每成功发送一条提醒后
- 日期变化时整体覆盖，**只保留当天**（Q3）；不含任务内容，不属于业务日志

```json
{
  "date": "2026-11-26",
  "runs": {
    "sync0900": "2026-11-26T09:00:04+08:00",
    "sync1650": "2026-11-26T16:50:06+08:00",
    "remind1700": "2026-11-26T17:00:21+08:00"
  },
  "sentOpenIds": ["ou_xxxxxxxx1", "ou_xxxxxxxx2"],
  "lastCalendarCheck": "2026-11-23"
}
```

| 字段 | 用途 |
|---|---|
| `date` | 状态所属日期，与当天不一致时清空重建 |
| `runs` | 当天各定时任务的完成时间；缺失表示未执行，用于**补执行判断**（02 Q8） |
| `sentOpenIds` | 当天已成功发送提醒的飞书用户，用于**每人每天最多 1 条**（F3） |
| `lastCalendarCheck` | 最近一次年底日历检查的日期，避免同一天重复提醒（F4.5） |

> 说明：`runs` 字段由补执行规则（02 Q8）引出，02 文档中只写了"当日已发送人员"，此处为补充。

```yaml
qd:
```
