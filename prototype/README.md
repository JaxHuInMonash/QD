# QD助手 · Jira 未完成任务提醒 —— 可交互原型

依据 [`docs/需求文档.md`](../docs/需求文档.md)（v1.0）制作的纯前端可交互原型，**全部为模拟数据**，不连接真实 Jira 与飞书。

## 打开方式

直接用浏览器打开 `prototype/index.html` 即可；或在项目根目录运行：

```
python -m http.server 8765 --directory prototype
```

然后访问 http://localhost:8765 。

## 页面构成

| 区域 | 对应需求 | 说明 |
|---|---|---|
| 顶部控制台 | —（原型专用） | 切换**当前身份**、**模拟日期**，手动触发 09:00 / 16:50 / 17:00 定时任务，模拟同步失败 |
| 📊 主表格 | F1、F2、第 5 章 | 12 个只读字段、5 个视图、"立即同步"按钮（仅管理员/负责人）、视图使用说明 |
| 💬 飞书消息 | F3、F5、第 6 章 | 当前身份收到的机器人私聊：17:00 提醒卡片、同步失败通知、未送达汇总 |
| ⚙️ 管理表格 | F4 | 排除名单、例外对应表、节假日日历；仅胡桓康、朱卓可访问 |
| 🧪 模拟 Jira | —（原型专用） | 模拟数据源，可改状态 / 经办人 / 是否在看板 / 删除 / 新建，用于观察同步效果 |

## 推荐演示路径

1. **每日提醒**：点「▶ 17:00 发送提醒」→ 打开「飞书消息」。身份为胡桓康时可看到提醒卡片和"未送达汇总"（陈晨邮箱对不上、孙伟已离职）。
2. **例外对应**：在「管理表格 › 例外对应表」把陈晨（chenchen）对应到飞书账号陈晨 → 点「下一天」→「▶ 17:00」→ 切换身份为陈晨查看。
3. **只保留未完成**：在「模拟 Jira」把某任务改为"已解决"或取消"在看板中" → 回到主表格点「立即同步」→ 该任务从表格消失。
4. **权限**：切换身份为李明 → "立即同步"不可用、管理表格无权限；"我的未完成"只显示李明的任务。
5. **异常处理**：控制台"下次同步"选"失败" → 「▶ 16:50」→「▶ 17:00」→ 胡桓康收到失败通知，提醒照常发出并注明"数据截至"上一次成功同步。
6. **法定工作日**：日期选 2026-11-27（示例节假日）→ 不同步、不提醒；选 2026-11-29（示例调休补班，周日）→ 照常执行；选普通周末 → 不执行。

## 与需求文档的对应要点

- R2 只保留未完成：同步后主表格 = 看板范围内状态类别非"完成"的任务。
- 消息格式：Story / Task / Bug 各显示总数，每类最多 3 条，按创建时间从早到晚；每条为"编号（可点）+ 标题 + Jira 状态"；末尾"查看全部 → 我的未完成"与"数据截至"。
- 手动同步只更新表格、不发提醒；每人每个工作日最多 1 条定时提醒。
- 不记录日志：原型中只有右下角的临时提示（演示用），产品本身不保存任何日志。

## 原型中的假设（需求文档未细化之处）

| 假设 | 说明 |
|---|---|
| 胡桓康具备主表格管理员权限 | 需求第 7 章写"运维负责人（如具备管理员权限）"可立即同步，原型按"具备"处理 |
| 某类数量为 0 时显示"共 0 条" | 需求 6.2 留给设计阶段，原型采用与示例一致的写法 |
| 手动同步时间取电脑当前时间 | 日期取模拟日期，时间取本机时钟 |
| 节假日日历为示例数据 | 2026-11-27、2026-11-29 仅为演示，正式需按国务院公布的安排录入 |
| 人员、Issue、邮箱均为虚构 | 邮箱统一使用 example.com |
